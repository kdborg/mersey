Mersey — per-technology benchmarks

One panel per web technology: wall-clock of the workload loop (self-timed in-language, median of 3, log scale) and memory (PSS of the browser process tree, workload page minus a blank page). The same program four ways — plain JS, transpiled JS, the WASM interpreter, and the Mersey engine native in the browser fork — each in Firefox (·ff), Chromium (·cr), Servo (·sv) and Ladybird (·lb). Every bar reports the same checksum. A dimmed row is honest absence (fetch has no native path in the Chromium fork; the Ladybird legs reach the echo endpoint by absolute URL + CORS, since its harness loads pages from file://). A memory bar of ≈0 is the measurement floor, not zero cost: Ladybird runs one process per test, so its memory is peak PSS minus a blank page's peak — a workload whose allocations stay under startup's crest is invisible to that method.
