Mersey — JS vs native

The same program as plain JavaScript and as native Mersey, in two arenas. Browser — each fork's own JS engine (js) vs the Mersey engine hosted natively in that fork (mersey), for Chromium (·cr) and Firefox (·ff). Command line — Node, Bun and Deno running the JS twin vs the Mersey CLI running the Mersey twin (compute workloads only — Node has no DOM). Time is the self-timed workload loop (median, log scale, same checksum on every bar); memory is the process's peak/PSS delta and is scaled within each panel, so revealing a fork re-scales those bars. Platform: macos. Rows appear only where measured: a fork that can't run a workload, a compute kernel with no in-browser JS twin (calls, fcompute, mathk — those live in the command-line arena), or a memory delta that never rose clear of the runner's baseline, simply has no bar. The grid is the comparison, not a field of n/a. Servo and Ladybird are measured too — the selector brings them in.
